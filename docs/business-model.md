## 0. 一页结论

如果只看五句话，是这五句：

1. **结构上这是个好生意，卡点 100% 在获客与留存。** 毛利率 >90%（AI 成本约 ¥0.004/句，
   见 §1.4），定价 ¥29/月、¥199/年也没问题。**没有任何一个问题是「成本太高」或「卖太便宜」。**

2. **你的原始计划有 4 条内容线 + 1 套分销，而你的资源是每周 10–20 小时。**
   这是一个数学冲突，不是态度问题。**必须砍到 1 主 + 1 辅。**

3. **抖音直播现在做，ROI ≈ 0。** 0 粉丝开播是对着空气讲 1 小时。但「直播」这个资产
   对你后面要做的合伙人体系是**必需**的——所以正确做法是**把它录成一份可复制的素材**，
   而不是每天真人开播。见 §5.2。

4. **¥399 合伙人 = 推广资格，是目前唯一命中《禁止传销条例》第七条(二)的结构**，
   而你的计划正是要把增长引擎架在它上面。**这会在放大增长的同时放大风险。**
   好消息：改成合规结构**只需要改一行代码 + 4 处准入判断**，而且**合规之后推广员基数
   从「付 ¥399 的人」变成「全部注册用户」——对增长是净利好。** 见 §7。

5. **最大的运营漏洞不在获客，在承接：会员到期时，你没有任何主动触达能力。**
   全仓库没有模板消息、没有推送、**也没有任何定时任务**（已核实）。注册→体验→到期→
   沉默→流失，这条链路上你一句话都插不上。**这是当前 ROI 最高的一个工程任务**，
   因为它作用于已经注册、已经体验过产品的人，**获客成本已付、边际成本近零**。
   ✅ 已拍板要做，完整设计见 **§11**。

6. ⚠️ **最后一条是最高影响的一条，也是本文档早期版本漏掉的：49 万句内容是从句乐部爬取导入的**
   （`docs/julebu-import-guide.md` + `scripts/import-julebu.ts`，数据里保留着
   `sourceName = "句乐部"`）。这意味着 **① 它不构成护城河、② 它是唯一一个索赔金额不确定的
   风险敞口、③ 它决定了「要不要换主体」这个问题的答案**。见 §1.1 与 §12.5。
   **建议尽早找律师评估一次内容来源问题，并把「自产原创内容」从可选项提升为战略必需项。**

1. **它不构成护城河**（本文早期版本在这里写错了）。内容既然来自主要竞争对手，

2. **它是当前最大的实质风险敞口**（已加入 §9 风险登记册）。这与传销/税务风险性质不同：
   那两个有明确的法定上限（行政处罚几万到几十万），而**版权与不正当竞争的索赔金额本质上无上限**，

3. **它是唯一一个「无限责任 vs 有限责任」会真正拉开差距的风险**——直接决定 §12 的主体结论。

> **因此「建设原创内容」从一个可选项变成了战略必需。** 原始内容是退路和地基，
> 不是加分项。好消息是：产品已经有 AI 生成 + 人工审核的能力
> （见 `docs/strategy.md` 的内容策略），把主力课程换成自产内容是可行的工程任务，
> 而不是重写产品。
>
> ⚠️ 以上是风险识别，**不是法律结论**。这件事的建议做法是**尽早找律师评估一次**，
> 而不是等对方发函。见 §12.6。

### 1.4 成本结构（AI 成本其实可以忽略，但有一个漏洞）

DeepSeek 于 2026-05-23 宣布 V4-Pro API **永久降价至原价 1/4**：
输入（缓存命中）¥0.025/百万 tok、输入（未命中）¥3/百万 tok、输出 ¥6/百万 tok
（[证券时报报道](https://stcn.com/article/detail/3924059.html)）。
我们实际用的是 `deepseek-flash`（`lib/llm.ts:13`），价格不高于该档。

按此估算（**假设**：系统提示约 600 tok，输出约 350 tok）：

| 动作 | 单次成本 | 说明 |
|---|---|---|
| 句子解析 `analyzeSentence` | **≈ ¥0.004** | 且系统提示可缓存命中，实际更低 |
| AI 对话 1 次 | **≈ ¥0.007** | |
| 阿里云短信 1 条 | ≈ ¥0.045 | 每个注册约 1.5 条 → **¥0.07/注册** |
| 有道 TTS | ≈ ¥0 | `tts_cache` 按 SHA-256 缓存后边际成本为 0 |

**结论：一个正常付费用户月成本 < ¥2，¥29 月卡毛利率 > 90%。这不是成本问题。**

**但存在一个真实漏洞——钻石经济：**

```
练习 1 句  →  最多 +25 钻石         (api/diamonds/earn, MAX_PERFECT_BONUS=20)
AI 对话    →  消耗 5 钻石/次         (api/chat/route.ts COST=5)
```

也就是说 **练 1 句最多能换 5 次 AI 对话（≈ ¥0.035 成本）**。若用户日练 20 句：

```
20 句/天 × 25 钻 = 500 钻/天 → 100 次对话/天 → ≈ ¥0.66/天 ≈ ¥20/月
```

- 对**免费用户**：纯亏损，且无上限。
- 对**月卡用户**：¥29 收入被吃掉约 70% 毛利。

这是不是「必然发生」取决于用户是否真把钻石全花在对话上——**但敞口是真实的**。
这也解释了为什么 `membership-growth-plan.md` 把「双货币拆分」列为 P1-1；
并且它是「¥399 终身 Pro」这个产品能长期成立的**前提**（终身用户若可无限刷 AI，平台永久亏损）。

> **建议（低成本版，不一定要立刻做全量双货币）**：先给**免费用户**的 AI 对话
> 加**每日次数上限**（如 5 次/天）。这一步就能堵住最大的亏损口，改动小于双货币拆分。

## 2. 商业模式：结构上成立，卡点在别处

### 2.1 价值主张（需要收紧的一句话）

现在的表述是「AI 驱动的中译英打字练习平台」——**「打字」是手段，不是卖点。**
对绝大多数中国学习者，打字速度从来不是痛点，**「读得懂但说不出来、写不出来」才是**。

建议对外的价值主张收成一句可验证的话：

> **用「敲出来」的方式练英语输出。不背单词，练产出的句子——练完就记住。**

它对应的是**主动回忆（active recall）+ 产出性练习**，这是有学习科学支撑的机制，
也是「背单词 App」做不到的事。这一点比「AI」更值得当卖点——AI 是 2026 年的人人都有，
**产出性练习 + 复习闭环才是竞品缺的**。

### 2.2 收入结构

| 收入来源 | 现状 | 建议 |
|---|---|---|
| C 端订阅（月/年） | 主力，已上线 | **唯一主线** |
| 终身 Pro ¥399 | 已上线 | 保留，但**与推广资格解绑**（§7） |
| 推广员佣金带来的分成后收入 | 已上线但准入受限 | 解绑后成为**主要放大手段** |
| 钻石充值 | 无 | **暂不做**（0 用户时无意义） |
| B 端（企业/学校/班级） | 无 | **暂不做**（销售周期长，兼职扛不住） |
| 兑换码（渠道承接） | 无 | **要做**，但可先用邀请码临时替代（§5.5） |

> **明确不做的事**：0–100 注册阶段不要碰 B 端、不要开钻石充值、不要做多语言、
> 不要做原生 App。这些都是「有 1,000 付费用户之后再谈」的选项。

### 2.3 单位经济学（LTV / CAC）

**LTV（假设，需用真实数据校准）**：

| 档位 | 客单价 | 复购/续费假设 | LTV |
|---|---|---|---|
| 年卡 | ¥199 | 续费率 30% → 1/(1−0.3) | **¥284** |
| 月卡 | ¥29 | 月留存 60% → 平均 2.5 个月 | **¥72.5** |
| 混合（60% 年 / 40% 月） | — | — | **≈ ¥199** |
| 扣除分销佣金（40% 用户来自推广、平均佣金 40%） | — | — | **净 ≈ ¥167** |

**CAC**：

| 渠道 | 成本 | 是否成立 |
|---|---|---|
| 自然内容 | 2h 时间/篇 | ✅ 成立（成本是时间，不是钱） |
| **分销（按成交付佣）** | ¥60–100/单 | ✅ **成立**——本质是「按结果付费的广告」 |
| **付费投流** | 见下 | ❌ **不成立** |

**付费投流为什么在数学上就不成立**（这一条请务必记住）：

```
乐观口径：教育类 CPC ¥1（小红书信息流偏低值）
落地页→注册 10%，注册→付费 5%
CAC = ¥1 / (0.10 × 0.05) = ¥200  ≥  净 LTV ¥167   →  亏损

中性口径：CPC ¥3，注册率 7%，付费率 3%
CAC = ¥3 / 0.0021 = ¥1,429                          →  巨亏
```

> **结论：¥199 年卡 + 无自动续费 + 50% 分销佣金，三者叠加后，付费买量在数学上不成立。**
> 所以每月 <¥1,000 的预算**不要投流**，全部投入到内容生产工具与素材制作。
> **唯一经济上成立的付费增长方式是分销**——因为它是按成交付费，不是按曝光付费。
> 这也是句乐部做「抖音主播分销」的根本原因：**它自己不用买量，主播替它买。**

> ✅ **决策已拍板（2026-09-29）：暂不投流。** 预算全部投入内容生产与素材制作。
>
> **复核条件**（不满足就不重新讨论）：第 6 个月时累计注册 > 3,000、累计付费 > 100，
> 且混合客单提升到 ¥300 以上——那时才用 **≤ ¥500** 做一次小规模投流测试。
> 在此之前，任何投流都是在**用现金补贴一个尚未验证的漏斗**。

### 2.4 打平点（让你对量级有感觉）

| 目标 | 需要的活跃付费会员数 | 对应注册量（3–4.5% 付费率） |
|---|---|---|
| 覆盖基础设施（≈¥400/月） | **约 24 个年卡等效** | 500–800 |
| 月净收入 ¥10,000 | **约 670** | 15,000–22,000 |
| 月净收入 ¥30,000 | **约 2,000** | 45,000–67,000 |

> **这张表是全篇最重要的一张。** 它说明：**¥10,000/月 是一个需要「万人级注册」的目标。**
> 任何「一个人发发笔记」的方案都无法到那里——**必须靠分销/直播/矩阵放大。**
> 反过来说，近 3 个月的目标**不该是收入**，而是**证明漏斗能转**（§8 的 gate）。

**我们的可攻击点**：复习闭环 + 内容规模 + 个性化诊断。

| 游戏化综合 | 多邻国 | 🟠 抢「坚持」这件事的心智，且免费 |
| AI 口语 | Speak、有道 Hi Echo、流利说 | 🟡 红海，大厂碾压，**不要进** |
| 真人/机构 | 新东方、线上外教 | 🟢 价位完全不同，不冲突 |

### 3.4 真正的竞争对手是「不练」

这是最重要的一条。**用户不会因为「句乐部更好」而流失，他会因为「今天不想练」而流失。**
所有留存设计（打卡、连胜、复习提醒、钻石）都是在跟「不练」竞争。
**而我们在 §1.2 第 9 条看到：打卡现在不给任何奖励——最便宜的每日回访钩子被浪费了。**

## 4. 盈利计划

### 4.1 定价建议

**现状**：¥29/月、¥199/年、¥399 终身。**缺季度档**，且年卡相对竞品偏低。

**建议（分轻重）**：

| 动作 | 优先级 | 理由 |
|---|---|---|
| **暂不涨价、暂不调价** | — | 0–100 注册阶段调价是「给空房间换壁纸」。**转化率低时涨价的收益远小于把转化率做上去。** |
| 补 **¥79/季** 档 | P2 | 填 ¥29 与 ¥199 的空档，对齐句乐部 ¥109/季 的锚点 |
| 年卡**首期优惠** ¥169 | P2 | 句乐部验证过的手段（¥365→首年 ¥299） |
| ¥399 终身**加稀缺性** | P1 | 改为「前 200 名 ¥399」，之后 ¥699。理由见下 |
| **绝不打折促销** | ✅ | 打折会永久拉低价格锚，且吸引最差的那批用户 |

**关于 ¥399 终身的真实风险（需要你现在就知道）**：

```
¥399 ÷ (¥199/年) ≈ 2 年
```

一个本来愿意连续订 5 年的用户，会一次性付 ¥399 → **你为 2 年的收入，卖掉了 5 年的服务+成本。**
在 0 用户时这是好事（现金流 + 种子用户 + 口碑），**但在 500+ 付费用户后它会开始吃掉年卡收入。**
所以：**现在保留并卖，但用「限量」给它一个自动退场机制。**
另外，§1.4 的钻石敞口必须堵上，否则终身用户可能永久亏损。

### 4.2 佣金结构建议

**现状**：首购统一 50%，续费 30%。问题在于**年卡也付 50%**——句乐部年卡只付 30%。

| 方案 | 月卡 | 年卡 | 终身 ¥399 |
|---|---|---|---|
| 现状 | 50% (¥14.5) | **50% (¥99.5)** | 50% (¥199.5) |
| **建议** | **50% (¥14.5)** | **35% (¥69.7)** | **固定 ¥100** |

理由：
- 月卡维持 50%：单笔小，靠高比例激励推广员**主推高转化的小单**，降低用户决策门槛。
- 年卡降到 35%：单笔金额大，¥69.7 相比句乐部年卡 ¥109（按 ¥365×30%）仍有竞争力，
  同时**每单多留 ¥30 用于产品与留存**。
- 终身改固定 ¥100：**比例制在这里最危险**——¥199.5 的佣金会让推广员疯狂推终身，
  而终身恰恰是 LTV 最低的档位（§4.1）。**用固定金额主动抑制它。**

### 4.3 三情景收入模型（12 个月累计）

**假设**：混合客单 ¥135（60% 年卡 / 40% 月卡 × 1.5 次续费），付费率见表，不含分销放大。

| 情景 | 12 个月注册 | 付费率 | 付费用户 | 累计收入 | 对应现实含义 |
|---|---|---|---|---|---|
| 保守 | 1,500 | 2.5% | 38 | **¥5,100** | 只发内容，不招募推广员 |
| 中位 | 6,000 | 3.5% | 210 | **¥28,400** | 1 个主渠道跑通 + 30 个活跃推广员 |
| 乐观 | 20,000 | 4.5% | 900 | **¥121,500** | 推广员网络起量 + 直播矩阵 |

**扣掉分销佣金后**（假设 40% 成交来自推广，平均佣金 40%）：
中位净 ¥23,800，乐观净 ¥102,000。

**这张表要说的话**：
- **保守情景（¥5,100/年）不足以支撑任何人的生活。** 只发内容的天花板就在那里。
- **要过 ¥10 万，唯一的路是「中位 → 乐观」的那一步，而那一步的杠杆 100% 来自推广员网络。**
- 所以：**你的原始计划中「合伙人二次拉新」这一环，是唯一能改变数量级的环节——
  其余（软文、直播、拉群）都是它的前置准备。**

### 4.4 什么时候可以开始拿钱

先说清楚，避免误判：**在约 670 个活跃付费会员之前，这个项目无法提供有意义的月收入。**
按中位情景，这大概在 **18–24 个月**。

**这不是劝退，是让你做对预期管理。** 由此推出两条策略建议：

1. **近 6 个月把「收入」换掉，改追「验证指标」**（§8 的 gate）。追收入会让你做短视动作
   （打折、乱推终身、上投流），而这些恰好都在损害长期价值。
2. **让项目同时产出第二份资产**：`docs/strategy.md` 里那条故事线
   （34 岁前端 → 用 AI 从零做产品自救）本身就是**高价值的内容资产**。
   它同时能带流量、建立信任、并成为你下一份工作/接单的作品集。
   **这不是分心，这是把同一份投入变现两次。** 建议内容选题里稳定留一条「开发/创业日记」线。

## 5. 推广计划：对你原方案的逐条体检

### 5.1 原方案体检表

你的原方案：软文（知乎/小红书）→ 抖音直播 → 拉群 → 合伙人员二次拉新 → 维护网站

| 环节 | 判定 | 理由与调整 |
|---|---|---|
| 知乎/小红书软文 | ✅ **保留，但只选 1 个主战场** | 你的资源只够一个渠道达标。选**小红书为主**（学习类转化路径最短），知乎做**同素材复用 + SEO 长尾**，不额外投入创作时间 |
| 抖音直播 | 🟡 **降级为「阶段 3」，且改为「录播素材」** | 0 粉丝开播对着空气讲 1 小时。见 §5.2 |
| 拉群分享推广 | ✅ **保留，且要早做** | 学习类私域转化率远高于公域。但要限量：**1 个群，手动运营** |
| 合伙人二次拉新 | ⚠️ **方向对，顺序错，且有合规风险** | 见 §5.4 和 §7。**这是阶段 3，不是阶段 2** |
| 稳定维护网站 | ✅ 保留，但要**限量** | 每周最多 3–5 小时，且只修阻断性 bug + 每周 1 个小改进。**不要开新功能线** |

**核心问题：4 条内容线 + 1 套分销 + 1 条产品线 = 6 个并行任务，每周 10–20 小时。**
平均每个 2–3 小时/周。**所有内容平台都有「发布量阈值」**——低于它，算法不会给你任何流量。
分摊的结局是每个渠道都拿不到流量。

### 5.2 为什么抖音直播现在不该做，以及该改成什么

**不该做的理由**：
- 直播是**实时**的：必须有固定档期（每周 3–5 场 × 1–2h），这对兼职是最高危的时间占用方式。
- 0 粉丝开播，场均在线个位数，**留存和转化都是 0**。
- 直播间**不能放外链**，承接要绕私信/主页——链路更长。
- 你**已经**有一个更高效的替代：把直播的「内容」做成图文/短视频，成本只有 1/10。

**该改成什么（关键翻转）**：

> 你要的不是「自己去直播」，而是**「让 30 个人替你去直播」**。
> 句乐部自己不是主播，**它养了一批主播**。

所以直播的正确用法是：**把它做成一份交给推广员的「标准作业素材包」**：

1. 你**只做一次**：录一场高质量直播（哪怕只有几个观众），主题定为
   「中译英翻译挑战：现场敲 50 句」。剪成 3–5 条短视频 + 1 份 30 分钟录播。
2. 配套一份 **《推广员开播手册》**：账号定位、选题模板、话术、**禁用语（§7.4）**、
   承接链路、佣金说明。
3. 推广员拿这份素材包去自己的账号开播——**他们有自己的粉丝，你有素材和分佣。**

这样：
- 你的投入：**一次性 8–10 小时**，不是每周 6 小时。
- 产出：一份可无限复制的资产。
- 而且它**顺便解决了「合伙人培训」问题**——你的原计划里，合伙人要学会你的打法，
  这个素材包就是培训内容本身。

**什么时候你亲自开播**：当私域群 > 200 人时。那时开播有基础观众，ROI 才为正。

### 5.3 改良版推广方案：一主一辅，一稿多投

**主战场：小红书**（周 3–4 篇）
**辅助：知乎**（周 1 篇长文，**由当周最好的小红书素材扩写而成，不额外选题**）

**为什么是小红书**：学习/职场类目用户密度最高，图文创作成本最低，
「笔记 → 私信 → 加群 → 领体验会员」这条链路最短。

**一稿多投的具体做法**：

```
周一：选题 + 写小红书笔记（图文）          1.5h
周二：发布；把同素材扩写成知乎长文          1.5h
周三：第二篇小红书                          1.5h
周四：发布知乎长文（含产品植入 + 邀请码）    0.5h
周五：第三篇小红书（产品/故事线）            1.5h
周六：回复评论/私信、拉群、跟进体验会员      2h
周日：数据复盘 + 下周选题                   1h
                                    合计 ≈ 9.5h/周
```

剩下 5–10 小时留给产品维护与用户运营（§6）。

**内容选题公式**（直接用，不要从零想）：

小红书（学习类高互动）：
1. 「中译英」翻车现场：这 10 句中国人必说错
2. 用打字的方式练了 500 个句子，第 7 天的效果
3. 英语学了 10 年还是说不出？问题不在词汇量
4. 每天 15 分钟「敲」英语，比背单词有用在哪
5. 四六级翻译真题，你敢现场敲一遍吗
6. 职场邮件必备 20 句，敲熟就能用
7. 我把英语练习做成了打字游戏（产品介绍向）
8. 实测：背单词 vs 敲句子，30 天后哪个记得牢
9. 出国旅游 50 句，敲一遍就记住
10. 英语输出训练的 3 个阶段，大部分人卡在第 1 个

知乎（长尾 + 信任）：
1. 为什么背了很多单词还是不会说英语？
2. 成年人英语退化后如何重建输出能力？

4. 34 岁前端失业，我用 AI 做了个英语产品（故事线，高赞潜力最高）

> 在 0 用户阶段，**「一个真实的人在认真做这件事」比「这个产品有多好」更能带来付费。**

### 5.4 推广员体系：为什么是阶段 3，不是阶段 2

你的计划是「冷启动 → 直播 → 拉群 → 合伙人员二次拉新」。**把分销放在第 4 步，但实质上
它是唯一能放大规模的一环——所以会忍不住想提前做。请先看这个数学**：

```
推广员的收入 = 他的流量 × 注册率 × 付费率 × 佣金

假设他带来 1,000 次曝光：
注册率 8% → 80 注册；付费率 3% → 2.4 单；年卡佣金 35% → ¥69.7 × 2.4 = ¥167
```

**一个月 ¥167。** 一个推广员做到这个数就会退出——**他会在第一周就放弃。**

**所以顺序必须是**：

```
① 你自己先跑通「内容 → 注册 → 付费」的最小闭环（拿到真实转化率）
② 把跑通的选题/话术/承接链路固化成素材包
③ 拿着「有人真的靠这个赚到钱」的证据去招募推广员
```

跳过 ① 直接招募推广员，结局是：**招 20 个人，一周内全流失，还留下「这个平台赚不到钱」的负面口碑。**
这种口碑在推广圈里传播极快，且极难挽回。

**招募推广员的三个来源**（阶段 3）：
1. **你自己群里的活跃用户**——他们已经在用、已经认可，转化率最高。
2. **句乐部/哇学社的现有推广员**——他们已经在做同类事，只需换供应链。这是最高效的来源。
3. **小红书/抖音上做英语学习内容的小博主**（1k–5 万粉）——他们缺变现方式，你缺流量。

> 第 2 条是最被低估的一条：**去搜「句乐部 邀请码」「哇学社 推广」，
> 那些发帖的人就是你的目标推广员**。他们已经证明了愿意为这种事投入时间，
> 而且句乐部年卡佣金只有 30%，你在月卡上给 50%。

### 5.5 承接链路（当前最大的漏点）

**现状链路**：小红书笔记 → （主页/私信）→ 手动引导注册 → 试学 3 句 → 领 5 天体验 → 到期 → ❌ **无任何触达** → 流失

**三个漏点与修法**：

| 漏点 | 现状 | 修法 | 成本 |
|---|---|---|---|
| 渠道来源无法追踪 | 无兑换码、无渠道码 | **临时方案**：为每个渠道建一个「渠道账号」，用它的 `inviteCode`（注册时已生成）当渠道码。**零开发量** | 0 |
| 领体验会员的触发太弱 | 只在非会员触到试学墙时提示 | 注册后**立即**弹「领取 5 天体验会员」；把它做成一次明确动作（句乐部做法） | 小 |
| **到期无任何触达** | **完全没有** | 建立生命周期消息体系：体验/月卡/年卡到期前提醒 + 到期后挽回 | **中（最高优先级）** |

> **第三行是本文档里 ROI 最高的一个工程任务，已拍板。完整设计见
> [§11 主动触达体系](#11-主动触达体系生命周期消息)。** 理由：它作用于**已经注册、
> 已经体验过产品、且已经证明了兴趣**的人。获取这批人的成本**已经付过了**，
> 而你现在**一次都没有提醒过他们**。会员到期结束得悄无声息，等于把最热的那批线索
> 直接倒进垃圾桶。
>
> **核查结论（2026-09-29）**：公众号客服消息**已实现**（`lib/wechat.ts:294`）、
> 模板消息**未实现**、短信**只有验证码签名/模板**、**全仓库没有任何定时任务**
> （`lib/commission-safety.ts:11` 明确说明）。从网页授权接口
> （`wechat.ts:106` 的 `sns/oauth2/*`）判断，公众号是**认证服务号**——
> 这意味着**模板消息可用**，到期提醒可以免费送达。

- ❌ 不在没有数据支撑时改定价

### 6.2 必须每周看的 5 个指标

| 指标 | 定义 | 健康线（**假设**，需用数据校准） |
|---|---|---|
| 注册 → 领体验会员率 | 领体验/注册 | **> 40%** |

## 7. 合规红线（这一节请务必完整读完）

> **本文不是法律意见。** 正式推分销前，请拿这一节与
> [distribution-compliance.md](distribution-compliance.md) 去给熟悉社交电商的执业律师审一遍。

### 7.1 你现在唯一命中的那条，正好是你要放大的那条

`distribution-compliance.md` 的自查结论是：九个审查要件里**命中一个**，
但它是权重最高的那个：

```
src/lib/subscription.ts:128
  if (!partner || !partner.isPartner) return      ← 佣金准入绑在付过 ¥399 上
```

**「付费才能取得推广资格」= 《禁止传销条例》第七条(二)的「变相入门费」。**

**为什么这件事对你的计划特别要紧**：你的计划是
「合伙人会员 → 分享直播模式 → 二次拉新 → 逐步扩大规模」。
也就是说，**你打算把增长引擎直接架在这条唯一命中的要件上。**
规模放大 10 倍，这个结构的暴露面也放大 10 倍。

**罚则不是「会不会坐牢」，而是这个**——最高检明确：

> 对于存在变相入门费、人头计酬……但**尚未形成 30 人以上传销组织**的，
> 由市场监管部门送达风险警示书，**督促平台紧急关停分销功能**。

**「紧急关停分销功能」意味着：你投入的所有推广员一夜失效，已发佣金可能被追缴。**
这才是真正的风险——它不是法律风险，是**业务被一夜清零的风险**。

### 7.3 「二次拉新」能做与不能做（你的计划直接涉及）

你说的「合伙人可以分享直播模式，让他们二次拉新」——**这个模式本身是合法的**，
只要严格守住下面这条线：

```
✅ 能做（单层直推）：
   A 推广 → B 注册并付费 → A 拿佣金
   A 教 B 怎么做内容、给 B 素材包 → B 去推广
   B 推广 → C 付费 → B 拿佣金（A 从 C 这里拿不到任何钱）

❌ 不能做（红线）：
   C 付费 → A 也拿钱（跨层级计提）
   按「发展了 N 个人」给奖励（人头计酬）
   「推荐满 10 人升级，佣金提高到 60%」（阶梯解锁）
   收培训费/保证金/指定礼包（任何名义的入门费）
```

**给推广员的培训材料里，绝不能出现这些词**：发展下线、团队计酬、层级返利、
无限代、见点奖、对碰奖、直推奖、拉人头。

**注意一个容易踩的坑**：你说「把直播的模式分享给他们」——**教方法完全没问题**。
但如果你说「你培养的下级推广员出单你也有提成」，那就**直接命中条例七(三)**。

### 7.4 禁用词清单（直播间/短视频/详情页/推广话术）

```
零风险 / 稳赚 / 躺赚 / 月入过万 / 一年回本 / 包赚
拉人头 / 发展下线 / 团队计酬 / 层级返利
加盟 / 代理费 / 门槛费 / 保证金
无限代 / 见点奖 / 对碰奖 / 直推奖
```

推广话术**只**描述：**推广者通过分享链接，按被推荐人的真实付费金额获得佣金。**

> **教育类额外注意**：不能说「保过」「提分 X 分」「7 天流利英语」。
> 教育广告的合规审查比一般商品更严。

### 7.5 税务（跟传销无关，但罚则很硬）

一旦跑分销就必然向个人付款，这触发两项**独立**义务：

1. **扣缴义务**：《个人所得税法》第九条——「以支付所得的单位或者个人为扣缴义务人」。
   平台就是扣缴义务人。**现在协议里写的「平台不承担代扣代缴义务」是错的，必须改。**
2. **涉税信息报送**：[《互联网平台企业涉税信息报送规定》（国令第810号）](https://www.gov.cn/zhengce/content/202506/content_7029052.htm)
   要求**季度终了次月内**报送从业人员身份与收入信息。
   **罚则：逾期不改处 2 万–10 万；情节严重责令停业整顿并处 10 万–50 万。**

好消息：`partner_commissions` 已记录 `partnerId`/`amount`/`availableAt`，
**数据基础是有的**，缺的是导出与报送流程。

### 7.6 上线前必须留档的证据

《推广规则》完整版本（含生效日期）· 佣金计算与订单流水 · 用户层级关系导出（证明只有一层）·
推广物料审核记录 · 退款与佣金冲正记录。

## 8. 90 天路线图（带判定标准）

> 设计原则：**每个阶段都有一个「不达标就不进入下一阶段」的 gate。**
> 这不是形式主义——它防止你在漏斗没转起来时就去放大，那样只会把漏的水放大。

### 阶段 1（第 1–4 周）：证明漏斗能转

**目标：拿到真实的转化数据，而不是新增用户数。**

| 动作 | 产出 |
|---|---|
| 修 §7.2 的合规解绑（1 行代码 + 准入 + 文案） | 推广资格对全部注册用户开放 |
| 上线 §6.3-1 体验到期主动触达 | 5 天体验到期前 24h 提醒 |
| 上线 §6.3-2 打卡奖励、§6.3-4 免费用户 AI 日限额 | 留存钩子 + 堵成本口 |
| 精选 20 门精品课，补齐封面/简介 | 新手入口不瘫痪 |
| 小红书周 3 篇 + 知乎周 1 篇（§5.3 选题） | 12–16 篇内容 |
| **手动加前 20 个用户的微信**,逐个聊 | 定性反馈 |

**🚦 Gate（第 5 周初检查）**：
- 注册 → 领体验率 **> 40%**
- 体验 → 付费 **> 3%**（样本至少 50 个领体验用户）
- D7 留存 **> 20%**

> **如果 gate 不过**：**不要加大内容投放。** 问题在产品或转化链路，不在流量。
> 回去做 §6.3 的 3/4 两项，并逐个问「体验未付」用户为什么。
> **在转化率 <1% 时加大投放，等于按比例放大浪费。**

### 阶段 2（第 5–8 周）：找到能复制的那个公式

**目标：把「哪条内容能带来付费」找出来，并固化。**

| 动作 | 产出 |
|---|---|
| 内容继续，但只保留数据最好的那 2 个选题方向 | 收敛选题 |
| 建 1 个用户群，每周 1 次轻量答疑 | 私域池 |
| 录制 §5.2 的「标准直播素材包」+ 写《推广员开播手册》 | **可复制的资产** |
| 上线兑换码/渠道码（或先用渠道账号的 inviteCode） | 渠道来源可追踪 |
| 招募 **5–10 个种子推广员**（来源见 §5.4） | 首批分销网络 |

**🚦 Gate（第 9 周初检查）**：
- 累计付费 **≥ 20 人**
- 至少 **2 个推广员产生了真实成交**（证明「别人也能卖」）
- 转介绍占比 **> 10%**

> **如果「2 个推广员有成交」不达标**：说明素材包/话术不行，或产品转化太弱。
> **此时绝不能招更多人**——先自己带着 1 个推广员跑一遍全流程，把卡点找出来。

### 阶段 3（第 9–12 周）：放大与复制

**目标：把验证过的公式复制出去。**

| 动作 | 产出 |
|---|---|
| 推广员扩到 **30+**，每人配素材包 + 手册 | 分销网络 |
| 你自己开播（此时群 >200 人，开播才有观众） | 直播渠道启动 |
| 补季度档 ¥79、年卡首期优惠 ¥169 | 定价结构补齐 |
| 上线「待付费邀请记录」视图（句乐部有，是驱动转化的抓手） | 运营工具 |
| 建立季度涉税信息导出流程 | 合规义务落地 |

### 三个月后的成功标准（写在开始之前）

| | 保守 | 达标 | 优秀 |
|---|---|---|---|
| 累计注册 | 500 | **1,500** | 4,000 |
| 累计付费 | 10 | **50** | 150 |
| 活跃推广员（有成交） | 0 | **10** | 30 |
| 累计收入 | ¥800 | **¥6,000** | ¥20,000 |
| **漏斗是否被证明** | ❌ | ✅ | ✅ |

> **注意最后一行。90 天的真正交付物是「一个被证明的漏斗」，不是那几千块收入。**
> 漏斗一旦被证明，第 4–12 个月就是纯粹的复制工作；
> 漏斗没被证明，赚到几千块也只是偶然，不可复制。

## 11. 主动触达体系（生命周期消息）

> **决策（2026-09-29）**：做，且是当前优先级最高的工程任务。
> 本章是**设计稿 + 实施规格**，代码尚未改动。
>
> **代码核查结论**（以下全部基于实际读码，不是推测）：
>
> | 能力 | 状态 | 位置 |
> |---|---|---|
> | 公众号全局 access_token（带缓存） | ✅ 已有 | `lib/wechat.ts:199` |
> | **客服消息**（主动发） | ✅ **已实现** | `lib/wechat.ts:294`，已在 `api/feedback/route.ts:73` 使用 |
> | 关注状态查询 | ✅ 已有 | `lib/wechat.ts:229` |

> | 会员档位区分 | ✅ 已有 | `api/auth/me` 的 `member_tier`：trial / monthly / yearly / partner / free |

### 11.1 为什么这件事比获客更值钱

一个注册用户的获取成本 = 内容生产时间 + 短信 ¥0.07。而**领了体验会员的人**，
是走完了「看到内容 → 注册 → 主动点领取」的人——**这是全站最热的一批线索，你已经付过钱了。**

现在的实情是：

```
第 0 天：领体验会员        ← 兴趣最高点
第 1–4 天：可能练习，可能忘了
第 5 天：会员静默到期      ← 你一句话都没说
第 6 天起：用户不知道自己失去了什么，流失
```

一条模板消息的边际成本是 **¥0**，一条短信 **¥0.045**，
而一次成功唤醒的价值是 **¥199（年卡）**。**ROI 量级差是 3–4 位数。**
这是全篇唯一一个「投入极小、杠杆极大」的动作。

### 11.2 渠道能力与限制（这决定了整个架构）

| 渠道 | 能触达谁 | 单条成本 | 时效窗口 | 内容限制 | 现状 |
|---|---|---|---|---|---|
| 公众号**客服消息** | 48h 内与公众号有交互的用户 | **¥0** | **仅 48 小时** | 无模板审核 | ✅ 已实现 |
| 公众号**模板消息** | **已关注公众号的全部用户** | **¥0** | 无窗口 | **仅限服务通知，禁止营销** | ❌ 未实现 |
| **短信** | 全部有手机号的用户 | **¥0.045** | 受时段限制 | 需专属签名 + 模板审核 | 🟡 仅验证码 |
| 小程序订阅消息 | 需有小程序 + 用户逐次授权 | ¥0 | 授权后 | 一次性授权 | ❌ 无小程序 |

**架构结论**：

```
关注了公众号 + 48h 内有互动   →  客服消息（免费、即时）
关注了公众号 + 超过 48h       →  模板消息（免费、无窗口）  ← 到期提醒的主力
未关注公众号                 →  短信（¥0.045，只在高价值触点用）
```

**由此推出一个战略动作（§6.3 第 5 项）：把「关注公众号」做进注册流程。**

原因很直接：**短信是唯一要花钱的渠道，而模板消息免费。** 关注率每提高 10 个百分点，
触达成本就下降一截。话术必须是**服务理由**——「关注后可接收学习报告与会员到期提醒」，
**不能写成「关注送会员」**（微信《运营规范》禁止以奖励诱导关注，
被判定后会限制接口权限，那整套体系就废了）。

### 11.3 场景矩阵

**P0 — 直接决定收入，第一批就做**

| 场景 | 触发时点 | 渠道 | 目标 |
|---|---|---|---|
| **体验会员即将到期** | 到期前 24h | 模板 + 客服 | **首购转化（单一最高价值触点）** |
| 体验会员已到期 | 到期日 +1 天 | 模板 | 挽回 |
| 月卡即将到期 | 前 3 天 / 前 1 天 | 模板 | 续费 |
| **年卡即将到期** | **前 7 天 / 前 1 天** | 模板 + 短信 | 续费（年卡是最值钱的续费，要更早、更用心） |
| 年卡已到期 | 到期日 +1 天 | 模板 + 短信 | 挽回 |

**P1 — 留存与激活**

| 场景 | 触发时点 | 渠道 |
|---|---|---|
| **领取体验会员后未练习** | 领取后 24h | **客服消息**（正好在 48h 窗口内） |
| 注册但未领体验会员 | 注册后 24h | 模板 |
| **打卡连胜即将中断** | 当日 19:00 仍未打卡且有连胜 | 模板 |
| 月卡已到期 | +1 天 / +7 天 | 模板 |
| 年卡已到期 | +3 天 | 模板 |

**P2 — 精细化**

| 场景 | 触发时点 |
|---|---|
| 连续 3 天未练习（付费会员） | 第 3 天 |
| 复习队列积压 > 20 句 | 每周一次汇总 |
| 付费后 7 天「学习成果报告」 | +7 天（提升续费与口碑） |
| 流失 30 天召回 | +30 天（低频，别骚扰） |

> **P1 第一行有个漂亮的巧合**：客服消息的 48h 窗口，正好覆盖「刚领取体验会员、
> 还没开始练」这个最该被推一把的时刻——**而且免费、无需模板审核、代码已具备。**
> 这是整个体系里**最容易先落地**的一块，建议当成第一周的验证性实现。

### 11.4 消息内容设计（关键约束：模板消息只能发服务通知）

模板消息**不能承载营销内容**。写错会被驳回，严重时处罚账号接口权限。所以：

```
❌ 不能写：「续费立减 30 元」「限时优惠，仅剩 2 天」「最后机会」
✅ 可以写：「你的体验会员将于 9月30日 到期」
```

**正确分工：模板消息只陈述事实，把转化放在落地页。**

```
【模板消息】会员到期提醒
  ├ 会员类型：体验会员
  ├ 到期时间：2026-09-30
  ├ 学习记录：已练习 47 句 · 待复习错句 23 个
  └ 备注：点击查看你的学习报告

        ↓ 点击跳转

【站内「到期挽留页」】← 这里才是转化设计
  ├ 你的学习报告（47 句 / 23 个错句已进入复习队列）
  ├ 未复习的错句列表（制造「不练就白练了」的损失感）
  ├ 续费入口 + 首期优惠
  └ 明确告知：到期后复习队列与历史记录会怎样
```

> **「模板消息只陈述事实 → 落地页做转化」是既合规又能转化的唯一解。**
> 任何试图把优惠塞进模板消息的做法，都会同时失去渠道和账号。

**文案的通用原则**：三条到期消息都要带上**该用户自己的学习数字**
（练了多少句、多少错句待复习）。模板消息支持变量，**带个性化数字的打开率与点击率
远高于通用文案**，而且它是「服务事实」而非营销——**两头都对**。

### 11.5 技术设计

**① 受保护的扫描路由**

```
POST /api/internal/lifecycle-scan
Header: x-cron-secret: $CRON_SECRET     ← constant-time 比较
```

- 新增 `CRON_SECRET` 环境变量，**不得复用其他任何密钥**
- **路由不接受任何入参**：触发条件全部由服务端时间与数据库推导。
  这一点是安全关键——**一个「能指定收件人」的接口等于把公众号变成了群发器**
- 内部按场景分批处理；单个用户异常只记录日志，**不中断整批**

**② 调度：服务器 crontab（本仓库的第一处定时任务）**

```cron
0 10 * * * curl -fsS -X POST -H "x-cron-secret: $CRON_SECRET" https://typenow.cn/api/internal/lifecycle-scan
0 19 * * * curl -fsS -X POST -H "x-cron-secret: $CRON_SECRET" https://typenow.cn/api/internal/lifecycle-scan
```

- **为什么是 10:00 和 19:00**：短信合规时段通常为 8:00–20:00，19:00 是当天最后一次
  能发短信的机会；同时它赶在「当日打卡截止」之前，正好服务 §11.3 的连胜提醒。
- ⚠️ **`deploy.sh` 需要一并加 crontab 安装步骤。** 本仓库此前没有任何定时任务
  （`lib/commission-safety.ts:11` 明确说明了这点），这是第一处——
  **不要让它在服务器上「手工配过一次就算完」，否则换机器就静默失效。**

**③ 幂等：新增 `notifications` 表**

```
唯一索引 uk_notification (user_id, scenario, channel)
```

- 同一用户、同一场景、同一渠道**只发一次**，由**数据库约束**保证，而不是代码里判空
- 沿用本仓库既有的「唯一索引 + `affectedRows` 判定」模式
  （参考 `lib/trial.ts:35` 的 `trial_claimed_at`、`uk_task_ref_type`）
- **先写入占位、再发送**，避免并发重复；发送失败标记 `failed`，
  按**有上限的短重试**处理（不要无限重试）

**④ 频率上限（必须有，否则会毁掉用户）**

- 每人每周**最多 2 条**主动消息；**到期类消息不计入**（它们有独立价值）
- 全局开关 `LIFECYCLE_ENABLED`，出问题**一键关闭**
- 同类消息之间至少间隔 24h

**⑤ 退订**

- `users.notify_opt_out`：用户回复「退订」或点击退订链接后置位
- **所有发送路径的入口都必须检查它**，不允许被任何逻辑绕过
- 短信必须附带退订方式（法规要求，见 §11.7）

**⑥ 数据基础**

到期扫描需要「谁在未来 N 天内到期」。`users.proExpires` 已存在，
`checkAndExpirePro`（`lib/subscription.ts`）也已处理懒过期。
**新增的只是「按时间窗口扫描」这个查询能力**，不需要改现有会员逻辑。

### 11.6 需要立刻启动的「非代码」前置事项（有等待时间，先做）

| # | 事项 | 在哪做 | 预计等待 |
|---|---|---|---|
| 1 | **确认公众号是认证服务号** | 公众平台 → 设置与开发 → 账号信息 | 即时 |
| 2 | **申请模板消息模板**（会员到期提醒 / 学习提醒） | 公众平台 → 模板消息 | **1–3 天** |
| 3 | **申请通知类短信签名 + 模板** | 阿里云短信控制台 | **1–2 天**（营销类更久） |
| 4 | **用户协议/隐私政策补「服务通知」条款** | `(public)/terms`、`(public)/privacy` | 即时 |

> **第 1 条必须先验证再动工。** 从 `wechat.ts:106` 使用网页授权接口
> （`sns/oauth2/access_token`）看，**强烈指向认证服务号**——订阅号没有网页授权权限。
> **但如果确认是订阅号，模板消息不可用**，整套体系只能退化成短信，成本结构完全不同。
> **这个前提决定后面的实现，务必先去后台确认。**
>
> **第 4 条是法律义务，不是可选项。**《个人信息保护法》要求明示同意，
> 而**现在注册流程没有这一项**——在发出第一条通知之前必须补上，
> 否则第一批营销性质的触达就是违规的。

### 11.7 合规要求（短信比想象中严）

- **《通信短信息服务管理规定》**：发送商业性短信息**须经用户同意**，
  并**提供退订方式**；发送时段受服务商限制（通常 8:00–20:00）。
- **《个人信息保护法》**：注册时必须**明示同意**接收服务通知（见 §11.6 第 4 条）。
- **模板消息**：只能用服务通知类内容；营销内容会被驳回，严重时**处罚账号接口权限**。
- **教育类文案**：不得出现「保过」「提分 X 分」等，与 §7.4 是同一套禁用词。

### 11.8 验收指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 到期前触达率 | 实际发出 / 应触达人数 | **> 90%** |
| **到期触达 → 付费转化** | 触达后 3 天内付费 / 触达人数 | **> 8%**（对照 §6.2 无触达基线 3%） |
| 公众号关注率 | 关注公众号的注册用户 / 总注册 | > 50%（决定触达成本） |
| **退订/投诉率** | 退订或投诉 / 触达人数 | **< 1%** |
| 短信占比 | 短信发送量 / 总触达量 | 越低越好 |

> **退订率是最重要的刹车指标。** 触达做过头会同时毁掉用户体验和公众号账号健康度——
> 后者一旦被限制接口权限，整套体系就没了。**宁可少发，不可多发。**

## 12. 主体与税务规划

### 12.1 已拍板决策（2026-09-29）

> **现阶段维持个体工商户，暂不设立公司。软性目标：连续 3 个月稳定月利润 > ¥10,000。**

决策理由（记录在案，便于将来复盘）：
- 0 付费用户阶段，有限公司的年维护成本（代账 + 对公户，约 ¥2,000–5,000/年）是纯负担。
- 有限责任在**无收入、无雇员、无佣金支出**时价值为零。
- 月度预算 < ¥1,000，不值得为「可能的风险」先付固定成本。

### 12.2 但这个决策必须配一个更早的硬触发条件

**主体切换的成本随规模单调上升，而不是下降。** 所以「等稳定盈利 1 万再考虑」
本身没问题，但它**不能是唯一条件**：

| 切换成本项 | 为什么随规模上升 |
|---|---|
| **微信支付商户号不能变更主体** | 换主体 = 重新申请商户号 + 重新签约审核；历史订单与结算流水要重新绑定 |
| 抖音/小红书/公众号企业号主体 | 重新认证；粉丝与内容资产的主体迁移麻烦 |
| 已注册的商标 | 需办**转让**（官费 + 代理，**6–8 个月**） |
| 分销佣金与扣缴记录 | 已产生的佣金、扣缴、报送记录要迁到新主体 |

### 12.3 修订后的触发条件（满足任一即启动「个转企」）

| # | 触发条件 | 为什么它可能比「利润 1 万」更早到 |
|---|---|---|
| 1 | **开始正式招募推广员、向个人付佣金（规模 > 10 人）** | 这一步同时触发**扣缴义务 + 季度涉税报送 + 行政责任**，个体户下**全部是你个人无限责任** |
| 2 | 月流水稳定 > **¥30,000** | 税负与责任风险开始实质化 |
| 3 | 需开专票 / 签 B 端合同 / 进抖音教育培训类目 | 主体类型可能**直接卡住资质** |
| 4 | 引入合伙人、给股权、融资 | 个体户**法律上不可能**有股东。**（注：雇工不是障碍——个体户可以合法雇工，此处早期版本写错了）** |

> **条件 1 大概率先于「利润 1 万」到达。**
> 所以准确的表述是：**「盈利 1 万」是软性目标，而「大规模招募推广员」是硬性红线——
> 后者一到就必须换主体，哪怕还没盈利。**
> 原因就是 §12.2 那张表：**在几十个推广员开始结算佣金之后再换主体，是一场灾难。**

### 12.4 个转企的操作要点

- 多数地区有**个体工商户转型升级为企业**的便利化通道，可保留字号与成立日期，
  具体口径问**当地市场监管局**。
- **注册资本不要写大**：新《公司法》（2024-07-01 施行）要求认缴出资 **5 年内实缴**。
  建议 10–50 万，不要写 1000 万。
- **一人有限公司**务必与个人财务严格分离（独立对公户、规范记账），
  否则可能被「刺破公司面纱」，股东对公司债务承担连带责任——**有限责任就白买了**。
- **商标**：用个体户执照现在就能注册（自然人注册也需经营主体资格证明）。
  建议**先注册、后转让**——TypeNow 是要长期做的品牌，**抢注风险大于转让成本**。
- **税务优惠（以当地税务机关口径为准，请代账确认）**：
  小型微利企业所得税实际税负约 5%（应纳税所得额 ≤300 万部分）；
  个体工商户经营所得 ≤200 万部分减半征收；小规模纳税人月销售额 ≤10 万免征增值税。
  相关政策目前延续至 2027 年底。

### 12.5 如果不换主体，到底会发生什么

**先把话说清楚：不换也能一直做下去。** 本文早期版本在讨论这件事时用了「灾难」这个词，
**措辞过重**。个体工商户在法律上完全可以：

- 申请微信支付商户号、开对公账户
- 开票（小规模纳税人可自开专票）
- 注册商标
- 入驻抖音/小红书企业号、企微
- **雇佣员工**（个体户可以合法雇工，这不是障碍）
- 长期经营——**没有「必须升格」的法定期限**

**所以真正的问题不是「会不会被迫停业」，而是一个保险问题：**

```
保费 = 一次性的切换成本（约 ¥3,000–5,000 + 迁移麻烦）
保额 = 个人全部财产（隔离掉公司层面的赔偿与行政处罚）
```

**要不要买这份保险，只取决于一件事：你的下行风险有多大。**

#### 你的下行风险不是零

| 风险 | 最坏情况 | 是否随规模放大 |
|---|---|---|
| **内容来源（§1.1）** | 版权 / 不正当竞争索赔——**金额本质上无上限**，且对方是有直接商业动机的同行 | 是（用户越多、收入越高，标的越大）|
| 广告法（教育类） | 罚款，通常按广告费用倍数或 10–50 万 | 是 |
| 涉税信息报送（§7.5） | 逾期不改 2–10 万；情节严重 10–50 万 | 是 |
| 个人信息保护 | 罚款 + 用户索赔 | 是 |
| 用户退款/纠纷 | 金额小 | 弱 |

**关键判断**：如果上表对你而言「最坏也就是几十万、且概率极低」，那无限责任的敞口是可以接受的，
**这份保费不划算**。但**第一行是个例外**——它的上限不确定，
而这恰恰是**有限责任唯一无法用别的方式替代的功能**。

> 这也修正了本文早期版本的说法。准确表述不是「大规模招募推广员就必须换主体」，
> 而是：**「当你开始承担金额不确定的下行风险时，有限责任才开始值钱。」**
> 招募推广员会**加速**这个时点到来（它同时引入扣缴义务、涉税报送、行政责任和纠纷），
> 但**它本身不是必须换主体的理由**。个人独资企业、个体户都能合法雇人和付佣金。

#### 那什么时候换才对

| 情形 | 建议 |
|---|---|
| 内容依赖未解除 + 开始有规模（>100 付费） | **认真评估换主体**，或**优先解决内容问题**（更根本） |
| 内容已换成自产 + 规模 <1,000 付费 | 个体户够用，省下保费 |
| 要融资、给股权 | 必须换（法律上不可能） |
| **收到律师函 / 约谈 / 风险警示书** | **立刻换 + 立刻找律师**，不要再等 |

> **优先级提醒**：如果只能做一件事，**先解决内容来源，而不是先换主体。**
> 换主体是把风险装进一个盒子；解决内容来源是让风险不存在。
> 前者花几千块但治标，后者是工程投入但治本。

### 12.6 本节不是专业意见

主体、税务、分销三件事都建议在动手前做一次**付费咨询**：
找**当地代账**确认税务与主体，找**熟悉社交电商的执业律师**审三份协议
（《用户协议》《推广合作协议》《隐私政策》）。
